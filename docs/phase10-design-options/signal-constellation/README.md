# Signal Constellation

## Rationale

Signal Constellation makes relationships the product signature. Holdings,
drivers, risk, research, and method appear as a navigable evidence map.
Selecting a node opens a plain-language inspector that answers “what deserves
attention?” before exposing calculations.

This option shows the strongest data-science identity. The spatial system is not
an illustration of planets; it is a map of how portfolio facts influence one
another.

## Typography approach

- A precise geometric or engineered display sans for chapter language.
- A highly readable humanist sans for explanations.
- Mono labels for ticker nodes, changes, timestamps, and data provenance.
- Moderate display scale; hierarchy comes from spatial focus and relationships
  as much as type size.

Exact families remain open. The mockup uses local system fallbacks.

## Color and atmosphere

- Deep graphite field with a faint coordinate lattice.
- Cool cyan for selected relationships, pale neutral nodes, and measured coral
  for negative contribution.
- Node state always pairs color with label, line style, size, or icon.
- Atmosphere comes from depth blur, connection intensity, and a distant
  instrument glow.

Mockup values are illustrative, not production tokens.

## Navigation and disclosure model

- Question nodes—Pulse, Drivers, Risk, Research, Method—anchor the map.
- Holding nodes connect to the questions they affect.
- A visible “What deserves attention” inspector is the primary reading surface.
- Selecting a node updates the inspector and URL state.
- A normal ordered chapter list mirrors the map and remains the keyboard/touch
  path.

## Dimensional treatment

- Nodes occupy shallow depth layers with selected relationships pulled forward.
- Connection lines encode contribution/relevance, not decoration.
- The camera does not need free movement; one bounded focus shift is enough.
- A complete 2D SVG/DOM implementation may outperform full 3D; the spike should
  prove whether WebGL creates a material advantage.

## Motion plan

1. One network-assembly moment reveals only the relationships needed for the
   default Pulse/attention story.
2. Node selection dims unrelated paths and brings the chosen evidence into
   focus.

No physics, free camera, continuous particle motion, or decorative starfield.

## Mobile adaptation

- Replace the map with a vertical “signal trail”: attention summary, connected
  holding chips, then chapter destinations.
- Preserve the selected node as a compact inspector card.
- Offer an optional simplified 2D relationship diagram below the explanation,
  never as the only navigation.

## Accessibility fallback

- Relationships are also expressed as text: “IBM and INTC contributed most to
  the shortfall.”
- Real buttons/list items mirror every selectable node.
- A hidden/visible structured relationship list backs the visual diagram.
- Reduced motion shows the final focused network immediately.
- Forced canvas/WebGL failure renders the semantic 2D trail.

## Technical risk

High. The graph must avoid becoming dense, ambiguous, or expensive. It needs
stable layout, bounded node count, deterministic relationships, clear focus,
screen-reader equivalents, and strong mobile simplification. The risk is
justified only if relationship exploration materially improves understanding.

## Resume-showcase strengths

- Strongest showcase of data modeling, explanatory visualization, and
  interactive systems thinking.
- Turns portfolio-specific relationships into a distinctive identity.
- Creates a credible bridge between product/frontend judgment and
  data-science capability.

## What the mockup is testing

- Can the relationship map answer a useful question before it feels technical?
- Are holding/driver links understandable without instructions?
- Does the inspector maintain a clear first-layer hierarchy?
- Can mobile preserve the relationships without shrinking the graph?
